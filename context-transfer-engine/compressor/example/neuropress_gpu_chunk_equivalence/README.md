# NeuroPress ↔ Clio callback-trace equivalence

Runs **native NeuroPress** and **Clio-NeuroPress** over the *same GPU-resident
chunk* and compares them **callback by callback**, reporting the **first point
of divergence** rather than only whether the final compressed bytes match.

```
bin/neuropress_gpu_chunk_equivalence [--out DIR] [--no-e2e] [--no-self-check]
```

Outputs into `DIR` (default `.`):

| File | Contents |
|---|---|
| `native_trace.json` | native's callback trace, per chunk |
| `clio_trace.json` | Clio's callback trace, per chunk |
| `callback_comparison.json` | per-callback verdicts, machine-readable |
| `callback_trace_report.txt` | the human-readable walk, verdicts and matrix |
| `e2e_selection.csv` | Clio's own selection log from the end-to-end run |

Exit code `0` = every chunk passed, `2` = at least one failed, `77` = no GPU
(reported as SKIP by ctest).

---

## Why it is shaped this way

**Native NeuroPress has no callback API.** That was the first thing checked, and
it matters: `gpucompress.h` exposes no registration, observer or hook function
of any kind. So rather than invent a parallel callback system that would only
ever observe the Clio wrapper, this harness uses what native actually has:

1. **Native's own stage entry points as the callback boundaries.** Every stage
   below is an exported entry point of `libgpucompress`, called in the order
   upstream's own AUTO path calls it (`gpucompress_compress.cpp:238-1173`).
2. **Native's own per-chunk diagnostics record.** `gpucompress_chunk_diag_t`,
   written by `recordChunkDiagnostic()` at the end of
   `gpucompress_compress_with_action_gpu` and read here through the public
   `gpucompress_get_chunk_diag`. Its ranking outputs (`out_top_actions`,
   `out_predicted_costs`, `NNDebugPerConfig`) are likewise read, not
   re-derived.
3. **CUPTI runtime-API callbacks** for the transfer and kernel record. This is
   the smallest instrumentation that answers "did this stage really run on the
   GPU" and "did anything sneak a D→H copy in here" — it observes the real
   `cudaMemcpy` / `cudaLaunchKernel` calls *both* implementations make,
   in-process, with neither project modified.

Clio's side is traced through the same taxonomy, calling the same functions its
compressor runtime calls.

## The stage map

| Callback | Native | Clio |
|---|---|---|
| `statistics` | `runStatsKernelsNoSync` | `ctp::ComputeDeviceStatsResident` |
| `inference` | `gpucompress_infer_gpu` | `NeuroPressCandidateStatsDevice` |
| `ranking` | `out_top_actions` / `out_predicted_costs` | the returned best-first order |
| `selection` | `decodeAction(action)` | `ranked.front()` |
| `diagnostics` | `gpucompress_chunk_diag_t` + a 24 B feature probe | `ctp::ReadDeviceFeatureStats` |
| `quantization` | `quantize_simple` | `ctp::…::QuantizeDevice` |
| `shuffle` | `byte_shuffle_simple` | `ctp::…::ByteShuffleDevice` |
| `compression` | `gpucompress_compress_with_action_gpu` | `CompressionFactory` preset → `Compress` |

Quantization runs **before** shuffle. That is the real order on both sides
(`gpucompress_compress.cpp:434-470`, `compressor_runtime.cc:2346-2465`), and the
taxonomy is written in execution order so an ordering divergence is detected
rather than hidden.

## What is asserted, and how

- **The chunk is GPU-resident from birth.** Each chunk is generated by a CUDA
  kernel into `cudaMalloc`'d memory; there is no host original. The pointer is
  then classified through `cudaPointerGetAttributes` and the run refuses to
  continue unless the driver itself says DEVICE.
- **Both sides read the same bytes**, and that is byte-compared rather than
  assumed.
- **Byte-level comparisons run on the device.** Only a 24-byte verdict comes
  back. Hashes are a fast diagnostic; the equivalence assertions are
  byte-for-byte.
- **Harness transfers are tagged** `TEST_HARNESS_TRANSFER` and excluded from
  every production transfer count. A production host round trip of anything
  approaching the chunk's own size is counted separately as a *bulk transfer*
  and fails the chunk if Clio makes one native does not.
- **The stage decomposition is checked against production.** The run also
  drives the whole chimod (`AsyncDynamicSchedule`) and compares the selection
  it logged against the traced one. If those disagree, the decomposition is not
  a faithful model of production and the report says so.

### Normalization

Only entries classified `kClioArchitectural` are removed, that classification
comes from a closed switch in `KindOf()`, and every removed entry is reported by
name. No NeuroPress functional stage can be normalized away.

### Two places where a difference is reported but not failed

Both are stated in full in the report; neither is silent.

- **Ranking ties.** When the two ranked orders differ, the harness checks
  whether every differing position sits between candidates the model scored
  *equally* — masked to −∞ (`nn_gpu.cu:238`), or bit-identical cost, which is
  common because predicted ratio saturates at the 100× cap. If so it is an
  ordering of a tie block, not a difference of opinion. Rank 0 is compared
  separately and unconditionally in `selection`.
- **Codec reproducibility.** Each side is also run a second time over the same
  chunk and compared against *itself*. nvcomp output is known to depend on
  manager reuse history, and a codec that disagrees with its own previous
  output cannot be used to judge the other implementation.

## Building

NeuroPress is not a Clio build dependency, so the target skips itself when the
native library or CUPTI is missing.

```bash
cmake -S ~/NeuroPress -B ~/np-build -DNVCOMP_PREFIX=<prefix with include/nvcomp.hpp and lib/libnvcomp.so>
cmake --build ~/np-build --target gpucompress -j

cmake -S . -B build -DCLIO_NEUROPRESS_SRC_DIR=~/NeuroPress -DCLIO_NEUROPRESS_BUILD_DIR=~/np-build
cmake --build build --target neuropress_gpu_chunk_equivalence -j
```

Registered with ctest as `cte_neuropress_callback_trace_equivalence`.
