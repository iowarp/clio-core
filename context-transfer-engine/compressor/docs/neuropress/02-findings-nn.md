# NN scope: host-vs-device cross-examination (NeuroPress b23b8f6 vs clio-core `neuropress-693-continued`)

**Audit basis.** The clio-core working tree changed *during* this audit (the branch's uncommitted device-stats work landed mid-read; `Load()`'s no-device behavior was changed from a warn-and-continue to a hard failure while it was being read). All PORT line numbers were re-verified against tree state with `md5(neuropress_nn_predictor.cc)=4c7c521605ec27c3453f16779c7b6d8f`, `md5(neuropress_nn_gpu_kernels.cu)=36898ad800541fedb9f18e6babb665df`.

**Findings: 10.**

## NN-1: Deferred decompression-head SGD is a CUDA kernel natively and pure host C++ in the port
- **Claim:** Native trains the decompression-time head (`w5` row 1 + `b5[1]`) in a device kernel, `nnBatchedDecompSGDKernel`, which recomputes the frozen 8->64->64->64->64 trunk on the GPU for every sample and updates weights in place in device memory. The port has no such kernel at all: `NeuroPressNNPredictor::TrainDecompHead` runs the identical arithmetic — per-sample trunk forward pass, gradient accumulation, norm, trust-region step, weight clamp — in scalar host C++.
- **Native evidence:** `src/nn/nn_gpu.cu:2382` `__global__ void nnBatchedDecompSGDKernel(NNWeightsGPU* __restrict__ weights, const DeferredDecompSample* __restrict__ samples, ...)`; trunk forward on device `:2432-2466` (`// Forward L1 (read-only, frozen)` ... `s_h4[t] = (sum > 0.0f) ? sum : 0.0f;`); device weight update `:2551-2558` (`weights->w5[1 * NN_HIDDEN_DIM + t] = fmaxf(-W_CLAMP, fminf(W_CLAMP, new_w));`); launched at `:2591` `nnBatchedDecompSGDKernel<<<1, NN_HIDDEN_DIM, 0, g_sgd_stream>>>(...)`.
- **Port evidence:** `context-transport-primitives/src/compress/model/neuropress_nn_predictor.cc:1088` `SGDActivations a = ForwardWithCache(x_norm);` (host forward pass, defined `:374`, nested scalar loops); host head output `:1090-1093`; host gradient accumulation `:1109-1113`; host weight update `:1151-1163` (`weights_[w5_row1 + t] = std::max(-kDecompWClamp, std::min(kDecompWClamp, w));`). The only `__global__` functions in `neuropress_nn_gpu_kernels.cu` are `InferKernel` (`:389`), `InferKernelDeviceStats` (`:427`), `SGDKernel` (`:621`). The port's header states the relocation outright — `neuropress_nn_gpu_kernels.h:58`: *"which does its arithmetic on the host so there is exactly ONE implementation of that ported math to audit"*.
- **Category:** host-compute (also missing-gpu-work: the kernel has no port)
- **Severity:** high
- **Reachability:** `Runtime::LearnDecompTime` -> `context-transfer-engine/compressor/src/compressor_runtime.cc:1040` `neuropress_predictor_->TrainDecompHead(batch_features, batch_times);`. Gate: `config_.neuropress_online_learning_enabled_` and a positive measured time (`compressor_runtime.cc:998`). Runs on **every** blob read once online learning is on, over *every* recorded chunk each time (`:1028-1032`), so host cost is O(batch x 12,608 MACs) per read.
- **How to falsify:** Show a `__global__` decomp-head kernel the runtime dispatches, or that `TrainDecompHead`'s loops compile as device code (`cuobjdump` the model library). Or show `nnBatchedDecompSGDKernel` is dead upstream — it is not; `runBatchedDecompSGD` launches it and is called from `src/api/gpucompress_learning.cpp:101`.

## NN-2: The port's decomp-head update round-trips the entire model host<->device on every call
- **Claim:** Native's decomp-head update never moves weights — the kernel mutates 65 floats in place. The port downloads all 13,576 parameters D->H, edits 65 on the host, and uploads all 13,576 back, per call, with synchronous `cudaMemcpy`.
- **Native evidence:** `nn_gpu.cu:2551-2558` (only writes); `runBatchedDecompSGD` `:2570-2618` copies only samples H->D and a 12-byte `SGDOutput` D->H.
- **Port evidence:** `neuropress_nn_predictor.cc:1070-1073` `if (gpu_weights_) { gpu::NeuroPressGpuDownloadWeights(gpu_weights_.get(), weights_.data(), biases_.data()); }` and `:1166-1169` `gpu::NeuroPressGpuUploadWeights(...)`. Transfers: `neuropress_nn_gpu_kernels.cu:272` `cudaMemcpy(host_params, &w->params, sizeof(host_params), cudaMemcpyDeviceToHost);`, `:297` (a *second* D->H inside the upload's read-modify-write), `:313` H->D. `sizeof(host_params)` = 13576x4 = 54,304 B -> ~163 KB moved to change 260 bytes.
- **Category:** added-host-roundtrip
- **Severity:** high
- **Reachability:** same as NN-1 (`compressor_runtime.cc:1040`). The port documents the correctness fallout at `neuropress_nn_predictor.h:362` (*"A Train() landing inside that window is silently reverted"*), which is why `model_mutex_` (`neuropress_nn_predictor.cc:1050`) exists; upstream needs no such lock.
- **How to falsify:** Show the download/upload pair is elided on the reachable path (it cannot be — `Load()` now hard-fails when `gpu_weights_` is null on a CUDA build), or that only 65 floats are transferred. `nsys` a learning run and count 54,304-byte `cudaMemcpy`s per read.

## NN-3: Cost computation and winner selection run on the device natively, on the host in the port
- **Claim:** Native computes `w0*ct + w1*dt + w2*ds/(ratio*bw)` per config in kernel registers and picks the winner on device (shared-memory tree reduction, or a 32-lane warp-shuffle bitonic sort that also emits the full ranked action list). The port's kernels emit only four raw per-candidate metrics; cost, ordering and argmax are all host C++ with `std::stable_sort`.
- **Native evidence:** `nn_gpu.cu:235-237` (inside `__device__ nnForwardPass`) `float io_cost = data_size_bytes / (ratio * bw); float cost = w0 * comp_time + w1 * decomp_time + w2 * io_cost; float rank_val = -cost;`. Device selection: `:382-390` (shared-mem tree reduction) and `:496-520`/`:348-368` (`float other_val = __shfl_xor_sync(0xFFFFFFFFu, my_val, j);` ... `out_top_actions[tid] = my_idx;`). Per-config costs on device `:470-471`. Host receives only `h_result.action` (`:2265`).
- **Port evidence:** kernels stop at raw metrics — `neuropress_nn_gpu_kernels.cu:381-384` `out_comp_time[cand] = fmaxf(1.0f, comp_time); ... out_psnr[cand] = psnr;` — no cost, no reduction, no sort in the file. Host cost model: `include/clio_ctp/compress/model/predictor.h:209-232` `double Score(...) const { ... double cost = w_cost_compress_time * ct + w_cost_decompress_time * dt + w_cost_io * io_cost; return -cost; }`; host ranking `predictor.h:380-403` `std::stable_sort(...)`. Grep for `__shfl`/`bitonic` in port production `.cu` files: none (only `predictor.h` comments and parity tests).
- **Category:** host-compute
- **Severity:** high
- **Reachability:** both port paths. Device: `neuropress_bridge.cc:257-258` `ranked = ctp::compress::model::CompressionPredictor::ScoreAndSort(...)`. Host: `neuropress_bridge.cc:260` `predictor.Rank(...)` -> `predictor.h:367`. Entered from `compressor_runtime.cc:675`/`:689` on every dynamic-mode chunk.
- **How to falsify:** Point to a device reduction/sort in the port that yields the selected action, or show `nnForwardPass`'s `rank_val` is not upstream's ranking key (it is — written to `s_vals[tid]` at `nn_gpu.cu:492`, sole reduction key). This is about *where* the arithmetic runs, not whether numbers match.

## NN-4: The PSNR quality-floor mask is a device masking term natively, a host post-filter in the port
- **Claim:** Native drives a failing config's rank value to `-INFINITY` inside the kernel before the on-device reduction, so it can never be selected on the GPU. The port's kernels have no `min_psnr` parameter; the filter is a host loop deleting entries from an already-ranked vector.
- **Native evidence:** `nn_gpu.cu:238-239` `if (quant == 1 && error_bound <= 0.0) rank_val = -INFINITY; if (min_psnr > 0.0f && psnr < min_psnr) rank_val = -INFINITY;`. `min_psnr` is a kernel parameter (`:287`, `:423`), supplied from `g_min_psnr_db` at `:1963`, `:2033`, `:2193`, settable via `gpucompress_set_min_psnr` (`gpucompress_learning.cpp:210-212`).
- **Port evidence:** neither `InferKernel` (`neuropress_nn_gpu_kernels.cu:389-412`) nor `InferKernelDeviceStats` (`:427-464`) takes a min-PSNR argument; `NeuroPressForwardShared` (`:332-386`) has no mask. Host filter: `compressor_runtime.cc:695-708` `if (context.target_psnr_ > 0) { ... if (stat.psnr_db_ < context.target_psnr_) continue; filtered.push_back(stat); ... }`.
- **Category:** host-compute
- **Severity:** medium
- **Reachability:** `compressor_runtime.cc:695`, gated on `context.target_psnr_ > 0`. With `target_psnr_ == 0` the port applies no floor at all.
- **How to falsify:** Show a min-PSNR argument threaded into the port's kernels, or that upstream's `g_min_psnr_db` default is 0 and Clio never sets `target_psnr_`.

## NN-5: On a CPU-only build the entire network — inference, SGD, decomp head — silently runs on the host
- **Claim:** With `CTP_ENABLE_NEUROPRESS_GPU=0` every GPU branch is preprocessed out, `Load()` still returns `true`, `IsReady()` still returns `true`, and the predictor answers from a full pure-C++ reimplementation of the forward pass and of `nnSGDKernel`'s backward pass. No warning, no error, no log line, no caller check. NeuroPress has no CPU implementation of this network at all.
- **Native evidence:** `src/api/gpucompress_compress.cpp:208-212` `if (ie != GPUCOMPRESS_SUCCESS || action < 0) { fprintf(stderr, "gpucompress ERROR: ALGO_AUTO requested but NN inference failed ..."); return GPUCOMPRESS_ERROR_NN_NOT_LOADED; }` and `:274-275`. Every layer lives in `nn_gpu.cu` `__device__`/`__global__` code.
- **Port evidence:** build gate `context-transport-primitives/src/compress/model/CMakeLists.txt:69` `target_compile_definitions(clio_ctp_compress_model PUBLIC CTP_ENABLE_NEUROPRESS_GPU=0)` (the `else()` of `if(CLIO_CORE_ENABLE_CUDA)` at `:29`). Host forward: `neuropress_nn_predictor.cc:333` `ForwardPass(...)`, reached from `:532-537` (`// CPU fallback: same per-candidate math as before, looped.`). Host backward: `:667` `// ---- CPU fallback (used when CUDA is unavailable ...)` through `:1022`. `TrainDecompHead` is host-side unconditionally. Nothing announces it: the `#if` block at `:148-181` — which *does* hard-fail on a CUDA build with no device (`:172-179`) — is entirely absent from a `=0` compilation, so control reaches `:183 is_ready_ = true; return true;` with no diagnostic. The advertised opt-out is unused: `grep -rn GpuInferenceActive` finds the definition (`neuropress_nn_predictor.h:116`), a comment, and **one test** (`parity/neuropress_device_path_parity.cu:319`) — no production caller. The runtime's only gate is `IsReady()` (`compressor_runtime.cc:671`, `:1001`, `:1351`), true on the CPU build.
- **Category:** silent-cpu-fallback
- **Severity:** high
- **Reachability:** any build with `CLIO_CORE_ENABLE_CUDA=OFF` plus a configured `neuropress_model_path_` (`compressor_runtime.cc:412-415`). Then `:689` -> `Rank()` -> `PredictBatch()` -> host `ForwardPass`; `:1547` `Train()` -> host backprop.
- **How to falsify:** Show a production caller consulting `GpuInferenceActive()`, or any diagnostic on the `=0` path, or that `Load()` fails there. Concretely: configure `-DCLIO_CORE_ENABLE_CUDA=OFF`, load a `model.nnwt`, run a dynamic-mode put, and show a message naming the CPU path.

## NN-6: The port's SGD blocks the host on a device readback per call; native deliberately made it fire-and-forget
- **Claim:** Native's `runNNSGDCtx` launches on a dedicated stream and returns immediately — no readback, no sync — with a comment saying that was the point. The port `cudaMalloc`s twice, launches, then does a **blocking** `cudaMemcpy` D->H of an `applied` flag, then `cudaFree`s twice, all while the caller holds `model_mutex_`.
- **Native evidence:** `nn_gpu.cu:2325-2334` `/* P6: fire-and-forget - no D->H readback or stream sync needed. ... Removing the sync drops g_sgd_mutex hold time from 0.1-0.5ms to ~10us, eliminating serialization across concurrent workers. */`. Samples pre-allocated per context: `gpucompress_pool.cpp:126-127`. Ordering vs inference is a GPU event: `nn_gpu.cu:2322` `cudaEventRecord(g_sgd_done, g_sgd_stream)` + `:2187-2188` `cudaStreamWaitEvent(stream, g_sgd_done, 0);`.
- **Port evidence:** `neuropress_nn_gpu_kernels.cu:1013-1027`: `cudaMalloc` x2, H->D, `SGDKernel<<<1, kHiddenDim>>>(...)`, `cudaMemcpy(&applied, d_applied, sizeof(bool), cudaMemcpyDeviceToHost);`, `cudaFree` x2. The lock spans it: `neuropress_nn_predictor.cc:654` `std::lock_guard<std::mutex> model_lock(*model_mutex_);` ... `:673`; the same mutex is taken by every reader (`:475`, `:591`).
- **Category:** added-host-roundtrip
- **Severity:** high
- **Reachability:** `compressor_runtime.cc:1547` (gated on online learning + `error_pct > neuropress_mape_threshold_`) and `:2024` (exploration).
- **How to falsify:** Show that `cudaMemcpy(&applied, ...)` does not serialize (it is the blocking form on the null stream), or that callers never contend. `nsys` a multi-worker learning run and show `Train()` ~= launch overhead, not kernel time.

## NN-7: The default (host-resident chunk) inference path allocates/frees five device buffers and calls `cudaDeviceSynchronize()` per chunk
- **Claim:** Native reuses `CompContext`-pooled buffers and ends with a single **stream-scoped** sync. The port's `NeuroPressGpuInferBatch` — taken whenever the chunk is not a device pointer — does five `cudaMalloc`s, a blocking H->D, a launch, a **device-wide** `cudaDeviceSynchronize()`, four blocking D->H copies, and five `cudaFree`s, per chunk.
- **Native evidence:** pre-allocation `gpucompress_pool.cpp:114-119`; reuse `nn_gpu.cu:2195-2198`; single stream sync `nn_gpu.cu:2235-2236`. `cudaDeviceSynchronize` appears nowhere in `nn_gpu.cu`.
- **Port evidence:** `neuropress_nn_gpu_kernels.cu:575-579` five `cudaMalloc`s; `:586-588` `InferKernel<<<num_candidates, kHiddenDim>>>(...); ok = cudaGetLastError() == cudaSuccess && cudaDeviceSynchronize() == cudaSuccess;`; `:601-605` five `cudaFree`s. The file concedes the gap in its own comment (`:471-474`: *"NeuroPressGpuInferBatch below does five cudaMalloc and five cudaFree on every call, i.e. per chunk. Upstream has none on that path"*) — but the fix (`InferScratch`, `:484-505`) was applied only to `NeuroPressGpuInferBatchDeviceStats` (`:518`), not to this entry point.
- **Category:** added-host-roundtrip
- **Severity:** medium
- **Reachability:** `compressor_runtime.cc:615-616` `np_device_path = num_elements > 0 && neuropress_active && ctp::IsDevicePointer(chunk);` — false for any host-resident chunk, the ordinary CTE case. `cudaFree` is itself device-synchronizing, so this is several full-device barriers per chunk.
- **How to falsify:** Show `NeuroPressGpuInferBatch` is unreachable in production, or that `InferScratch` also covers it (it does not). Instrument it with a counter under a normal put workload.

## NN-8: SGD training features are a device-resident struct natively and a host-built array in the port
- **Claim:** Native's SGD kernel takes `const AutoStatsGPU* d_stats` and reads entropy/MAD/second-derivative straight from device memory — the same struct inference used, never copied to host; its `SGDSample` is 20 B of action + labels. The port's `NeuroPressGpuSGDSample` carries a host-built `float raw_input[8]`, so the statistics must be materialized on the host.
- **Native evidence:** `nn_gpu.cu:622` `const AutoStatsGPU* __restrict__ d_stats,`; device reads `:656-658`; in-kernel input assembly `:700-714`. `SGDSample` = `{int action; float actual_ratio, actual_comp_time, actual_decomp_time, actual_psnr;}` (`src/nn/nn_weights.h:38-44`). Call site reuses the inference stats pointer: `gpucompress_compress.cpp:721`.
- **Port evidence:** `include/clio_ctp/compress/model/neuropress_nn_gpu_kernels.h:122-128` `struct NeuroPressGpuSGDSample { float raw_input[8]; ... };`; kernel standardizes from it at `neuropress_nn_gpu_kernels.cu:633`. Host assembly `neuropress_nn_predictor.cc:665-666`. Host materialization: `compressor_runtime.cc:1364-1366` under `:1341-1342` *"snapshot the intrinsic data features NeuroPress's own prediction was based on"*. On a device chunk this is a **second** full statistics pass plus a D->H sync.
- **Category:** device-struct-became-host
- **Severity:** medium
- **Reachability:** `compressor_runtime.cc:1349-1366`, gated on `neuropress_online_learning_enabled_`, before `Train()` at `:1547`.
- **How to falsify:** Show a port SGD entry point accepting a device stats pointer, or `raw_input[]` filled from device memory. Or show upstream's `nnSGDKernel` receives host-built features (it does not — the only H->D payload is `SGDSample`, `nn_gpu.cu:2292-2294`).

## NN-9: Outputs 4-7 and the per-config debug array are computed on device natively and are absent from the port's kernels
- **Claim:** Native inverse-transforms all eight outputs on device — including `rmse`, `max_error`, `mae`, `ssim` — and fills a 9-field-per-config `NNDebugPerConfig` array for all 32 configs on device. The port's kernels compute the eight raw activations but transform and emit only four.
- **Native evidence:** `nn_gpu.cu:207-215`, written `:246-249`; per-config debug on device `:455-466`; surfaced `:2260-2263`; consumed by `src/api/gpucompress_diagnostics.cpp:153-156`.
- **Port evidence:** `neuropress_nn_gpu_kernels.cu:358-362` computes all eight (`s_y[t] = o;`) but `:366-384` transforms/stores only 0-3 — `s_y[4]`..`s_y[7]` are dead. No `NNDebugPerConfig` equivalent. (The port's *host* `InverseTransform`, `neuropress_nn_predictor.cc:421-455`, does handle all eight — but nothing reads them: `CompressionPrediction` (`predictor.h:90-122`) has no such fields.)
- **Category:** missing-gpu-work
- **Severity:** low
- **Reachability:** always — both port kernels drop 4-7. Impact bounded: upstream's 4-7 feed *diagnostics only* (only consumers are `gpucompress_diagnostics.cpp:153-156` and pass-throughs). Lost observability, not a different selection.
- **How to falsify:** Show the port emits these from a kernel, or that upstream's 4-7 influence selection (they do not — `rank_val` at `nn_gpu.cu:236-237` depends only on ct/dt/ratio plus the psnr mask).

## NN-10: The port launches both NN kernels on the legacy default (null) stream; native never does
- **Claim:** Native launches inference on the caller's `CompContext` stream and SGD on a dedicated `g_sgd_stream`, ordered only by a CUDA event, so they run concurrently. The port launches `InferKernel` and `SGDKernel` with no stream argument — the legacy default stream, which implicitly synchronizes with every blocking stream in the process.
- **Native evidence:** `nn_gpu.cu:2190` `nnFusedInferenceKernel<<<1, NN_NUM_CONFIGS, 0, stream>>>(`, `nn_gpu.cu:2302` `nnSGDKernel<<<1, NN_HIDDEN_DIM, 0, g_sgd_stream>>>(` (`gpucompress_api.cpp:196`); cross-stream ordering by event, `nn_gpu.cu:2187-2188`. No kernel in `nn_gpu.cu` launches without an explicit stream.
- **Port evidence:** `neuropress_nn_gpu_kernels.cu:586` `InferKernel<<<num_candidates, kHiddenDim>>>(...)` and `:1021-1022` `SGDKernel<<<1, kHiddenDim>>>(...)` — neither passes a stream. The stream they implicitly barrier against is blocking: `preprocess/data_stats_gpu_kernels.cu:220` `cudaStreamCreate(&p->stream)`. (`NeuroPressGpuInferBatchDeviceStats` is the exception and does it right: `:536` `InferKernelDeviceStats<<<num_candidates, kHiddenDim, 0, st>>>(`.)
- **Category:** added-host-roundtrip
- **Severity:** medium
- **Reachability:** `SGDKernel` on every `Train()` (`compressor_runtime.cc:1547`, `:2024`); `InferKernel` on every host-resident-chunk ranking (`:689`).
- **How to falsify:** Show the build uses `--default-stream per-thread` (no such flag in `compress/model/CMakeLists.txt:43-66`), or that no other blocking stream is ever concurrently active. An `nsys` timeline showing `SGDKernel` overlapping stats-stream work disproves it.

# Subcategories that yielded nothing (stated explicitly)

- **Replay buffer.** There is **no replay buffer in NeuroPress at b23b8f6** — `grep -rn replay src/ include/` is empty. Only `tests/nn/test_replay_buffer.cpp` references `gpucompress_replay_buffer_clear()` / `gpucompress_set_replay_enabled()`, not declared in `include/gpucompress.h`. The port's host `decomp_features_` map is not a regression: native's own deferred-decomp sample source, `DiagnosticsStore` (`src/api/diagnostics_store.hpp:38-95`, `realloc`'d host array behind a mutex), is host-resident too and swept on the host (`gpucompress_learning.cpp:77-97`).
- **Forward-pass layer placement.** On the port's GPU path all five layers, standardization, and the log1p/expm1 inverse run inside the kernel (`neuropress_nn_gpu_kernels.cu:332-386`, `:403-407`, `:441-459`). No layer arithmetic moved to host there.
- **Weight residency across calls.** The port keeps weights, `log_var`, `sgd_call_count` in device memory for the handle's lifetime (`neuropress_nn_gpu_kernels.cu:65-92`, allocated once in `NeuroPressGpuLoad` `:213-261`); no per-call weight re-upload. Matches `nn_gpu.cu:64` + `:1774-1790`. Sole exception is `TrainDecompHead` (NN-2).
- **Runtime (non-build) silent fallback on a CUDA build.** Now closed in the working tree: `neuropress_nn_predictor.cc:157-180` hard-fails `Load()` when the device handle cannot be created; the device-stats path refuses rather than substituting (`neuropress_bridge.cc:244-256` `return {};`, logged at `compressor_runtime.cc:725-731`). The remaining silent path is build-gated only — NN-5.
- **`dense_nn_predictor.cc`/`.h`.** A legacy Clio-only MiniDNN/Eigen model with no NeuroPress counterpart, no CUDA, selected only when no qtable/linreg/NeuroPress model is configured (`compressor_runtime.cc:387-391`). Config-visible change of model, not a relocation.

# Methodology note on the port's parity comments

Every upstream citation was checked against `nn_gpu.cu` rather than trusted. Verified accurate: `nn_gpu.cu:64`, `:217-231`, `:238`, `:239`, `:1319-1326`, `:1380-1402` (anti-flip dot is trunk-only — the port's `kOffW5` cutoff at `neuropress_nn_gpu_kernels.cu:961` is a correct reading), `:1413`, `:1523-1528`, `:1560`/`:1566`, `:1674`, `:1745-1750`, `:1944-1971`, `:2236`, `:2551-2558`, and `gpucompress_compress.cpp:208-212`/`:281-282`. Two comments are stale but have **no** host-vs-device consequence, so are not findings: `neuropress_bridge.h:111-112` claims the device path *"falls back to the host ranking internally if device inference fails"* while the code correctly returns `{}` (`neuropress_bridge.cc:255`); and `neuropress_nn_gpu_kernels.h:135-137` says the EMA gradient lives *"in the device weight handle"* while it is a `thread_local` buffer (`neuropress_nn_gpu_kernels.cu:177-189`).
