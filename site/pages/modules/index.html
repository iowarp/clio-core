How modules fit together

A module (a ChiMod) is a unit of code that the runtime hosts as a pool. A pool has a name, a numeric pool_id, and containers on the nodes it spans, and it executes its operations as tasks in the runtime's worker threads. Clients and other modules address a pool by its id.

The data-path modules form an interposition chain. Each one is configured with a next_pool_id: it handles the operations it cares about (the indexer, when composed, records what is written, the shm cache answers metadata from shared memory, the write-back cache acknowledges writes in RAM and flushes them later, replication fans writes out to copies) and forwards everything else to the pool below. Two CTE cores sit at the bottom of the chain, one volatile and one persistent, and place data on block devices. Because each interposer forwards what it does not handle, you can remove one from the chain, or insert another, without changing the modules around it. The interposition chain covers the mechanism.

The default composition

The runtime's default configuration (context-runtime/config/clio_default.yaml) composes this stack, top to bottom. Requests enter at the top and travel down:

  1. clio_cae_coreAssimilation: imports external data into the store400.0
  2. clio_cte_core_shm_cache_writethruCaches tag and blob metadata in shared memory that clients map; the chain top568.0
  3. clio_cte_core_persist_write_backAcknowledges writes in the volatile core and flushes them to the persistent one567.0
  4. clio_cte_core (volatile)RAM tier; empty after every start540.0
  5. clio_cte_replicationWrites durable copies on the write-back flush path561.0
  6. clio_cte_core (persistent)Disk tiers with the metadata log512.0
  7. clio_bdevBlock devices: RAM, files, cloud buckets301.0

The filesystem (clio_cte_filesystem) and the stream module (clio_cte_stream) also enter the data path at the shm cache. The compressor, when composed, sits between the shm cache and the write-back cache. The indexer (clio_cte_indexer, 564.0) is opt-in and commented out in the file: to enable keyword search, uncomment it, set the shm cache's entry_pool_id to "564.0", and point the CAE, stream and filesystem entries' next_pool_id at "564.0". The cache module (clio_cte_cache, 563.0) is built but not composed by default. A compose that reuses a pool_id is refused at startup. A trimmed version of the default YAML:

compose:

    bdev_type: ram

    pool_query: local

      - path: "ram::cte_ram_tier1"

    pool_name: clio_cte_replication
    pool_query: local
