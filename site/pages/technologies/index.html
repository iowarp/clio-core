The composable I/O stack

A data-intensive pipeline moves the same bytes through several systems: a simulation writes checkpoints, an analysis job reads them back, a model trains on them, an agent searches them. Each hop usually means a different storage system, a copy, and a format. CLIO Core gives every hop the same substrate. You pick the modules a stage needs and the runtime wires them together:

  • Block devices for RAM, NVMe, SSD, disk, GPU memory, Amazon S3 and Google Cloud Storage, plus safe_bdev, which erasure-codes across several of them.
  • The Context Transfer Engine (CTE), which stores tags and blobs across those devices, scores each tier and moves data between them.
  • Adapters that put an interface in front of the CTE: a FUSE mount, POSIX and MPI-IO interceptors, HDF5 and ADIOS2 plugins, and paged vectors for CPU and GPU memory.
  • Data operators that sit in the chain between an adapter and storage and index, compress, transform or route data on the way through.

Every product below runs on the same runtime, so the data a pipeline stage writes through one product can be read through another without a copy.

How the numbers on these pages were measured

Every figure on the technology pages comes from a benchmark in the repository, with its hardware and its caveats. Where a comparison favors another system, the page says so. Most runs are single runs on one machine or a small allocation; treat them as measured examples, not guarantees for your hardware. Each page links the source document so you can rerun it.
