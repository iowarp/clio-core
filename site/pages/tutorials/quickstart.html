1. Where the default configuration comes from

clio-run start reads one YAML file. The first of these that exists wins:

  1. The file named by CLIO_SERVER_CONF, if you set it before starting.
  2. ~/.clio/clio.yaml. A source or package install copies the default configuration there the first time, and never overwrites a file that already exists.
  3. The default configuration bundled in the pip wheel, clio_default.yaml.

So a fresh install runs the default stack with no configuration step. If you installed an earlier release, your ~/.clio/clio.yaml is that release's default, not the one described here: compare it with the clio_default.yaml of your install, or move it aside to fall back to the bundled default.

2. What it composes

The compose section creates these pools, one container of each on this machine. Data written through the filesystem enters at the shm cache and flows down the table; the write-back cache acknowledges it once it is in RAM and flushes it to disk later:

PoolModuleRole
560.0clio_cte_filesystemThe filesystem. Maps paths to tags and file offsets to 1 MiB page blobs; journals its directory tables to ~/.clio/cfs_namespace_log.
565.0clio_cte_streamEach file's logical size, and appends from several writers. It has no size log in the default file.
568.0clio_cte_core_shm_cache_writethruThe top of the chain, where clients, the filesystem, the stream pool and the CAE enter. Caches tag and blob metadata in a shared-memory segment (256 MB) that programs on this machine map (md_only: true: no blob bytes).
567.0clio_cte_core_persist_write_backWrite-back cache. Lands each write in the volatile core and acknowledges it; flushes dirty data every 10 s through replication to the persistent core, and on fsync.
540.0clio_cte_core (volatile)The RAM tier, up to 80% of system memory. Empty after every start.
561.0clio_cte_replicationThe flush path to the persistent core; one copy of every blob (replication_factor: 1).
512.0clio_cte_core (persistent)A 10 GB file tier at ~/.clio/cte_disk_tier.dat with persistence_level: temporary, plus a metadata log at ~/.clio/cte_metadata_log.
400.0clio_cae_coreImports external data (HDF5, cloud buckets) into the chain top. Not on the file path.
301.0clio_bdevThe RAM block device behind the runtime's shared-memory allocator.

The indexer (keyword search, 564.0), the compressor (562.0) and the summarizer (401.0) are in the file but commented out. To enable the indexer, uncomment it, set the shm cache's entry_pool_id to "564.0", and point the CAE, stream and filesystem entries' next_pool_id at "564.0"; Query files from Python walks through it. Every pool needs its own pool_id: a compose that reuses one is refused at startup.

3. What it assumes

  • One machine. There is no hostfile, and every pool is local. For a cluster, add a hostfile; see Context FS usage.
  • Memory to spare. The RAM tier may grow to 80% of system memory. It fills lazily, so it costs nothing until you write data. On a shared or busy machine, set a smaller capacity_limit on the volatile core's RAM tier (see Compose local tiers).
  • Disk under your home directory. The disk tier is a file at ~/.clio/cte_disk_tier.dat, capped at 10 GB, and the write-back cache flushes everything you write to it. Files larger in total than that need a bigger tier. clio-run start --disk <dir> moves the storage root, and with it all on-disk state, to another directory.
  • Temporary storage. The only disk tier's persistence_level is temporary, no tier is long_term, and the stream pool has no log_path, so file sizes are not kept across a restart. This is a scratch filesystem, not a place to keep data. There is one copy, on this machine. To keep data, copy it out, or build a persistent local filesystem.
  • Free ports. The runtime uses the base port 9413 and the ports just above it, and refuses to start if one it binds is taken; set CLIO_PORT to move the whole range.
  • A local listener. On a single machine, set CLIO_BIND_ADDR=127.0.0.1 before starting the runtime and the mount, as below; on Windows this also avoids a firewall prompt.
  • Case-sensitive names. a.txt and A.txt are different files, on Windows too. For NTFS-like matching set case_insensitive: true on the filesystem entry before the volume is first created.
  • Writes acknowledged in RAM. The write-back cache holds the bytes; the shm cache holds metadata only. Data not yet flushed lives only in RAM until the next 10 s flush or an fsync. A program can keep a single put out of the shm cache segment with Context::kBypassShmCache in the context's op_flags_; the client then sends a task instead.
  • No keyword search. The indexer is opt-in (see above). Name and time queries work without it.

4. Start the runtime and mount

Start the runtime, then mount in a second terminal. CLIO_WITH_RUNTIME=0 attaches the FUSE daemon to the runtime you started instead of starting a private one, so other programs see the same files.

Linux

$ export CLIO_BIND_ADDR=127.0.0.1
$ clio-run start

$ export CLIO_BIND_ADDR=127.0.0.1
$ mkdir -p ~/clio-mnt
$ CLIO_WITH_RUNTIME=0 clio_cte_fuse ~/clio-mnt -f

Needs the system FUSE 3 package; see FUSE on Linux.

macOS

$ export CLIO_BIND_ADDR=127.0.0.1
$ clio-run start

$ export CLIO_BIND_ADDR=127.0.0.1
$ mkdir -p ~/clio-mnt
$ CLIO_WITH_RUNTIME=0 clio_cte_fuse ~/clio-mnt -f

Needs macFUSE and a source build of the daemon; see FUSE on macOS.

Windows

PS> $env:CLIO_BIND_ADDR = "127.0.0.1"
PS> clio-run start

PS> $env:CLIO_BIND_ADDR = "127.0.0.1"
PS> $env:CLIO_WITH_RUNTIME = "0"
PS> clio_cte_fuse Z: -f -o uid=-1,gid=-1

Needs WinFsp; see FUSE on Windows. -o uid=-1,gid=-1 makes the files belong to you, which tools such as git check.

-f keeps the daemon in the foreground; leave both terminals running.

5. Use it

The mount is an ordinary directory:

Linux, macOS

$ echo "hello" > ~/clio-mnt/hello.txt
$ cat ~/clio-mnt/hello.txt
hello
$ clio-run status
RUNNING

Windows

PS> Set-Content Z:\hello.txt "hello"
PS> Get-Content Z:\hello.txt
hello
PS> clio-run status
RUNNING

6. Unmount and stop

Linux

$ fusermount3 -u ~/clio-mnt
$ clio-run stop

macOS

$ umount ~/clio-mnt
$ clio-run stop

Windows

PS> Stop-Process -Name clio_cte_fuse -Force
PS> clio-run stop

Unmount first: the daemon ignores Ctrl+C. This is temporary storage: copy out anything you want to keep before you stop it. clio-run start --fresh always starts from an empty store.
