1. What CLIO Kit gives your agent

CLIO Kit is IOWarp's marketplace of agent skills, MCP servers and plugins for scientific computing. Its clio-core bundle holds a skill for composing a storage system, one skill per shipped module, and skills for writing new modules and GPU kernels. A skill is a folder of instructions that the agent loads when your request matches it. Each module skill lists every configuration key with its default, the module's client API, and what it loses to each kind of failure, so the agent does not need the CLIO Core source. These skills call no MCP server.

SkillThe agent uses it to
storage-composeChoose and order modules, write the compose list, and state what is durable, consistent and available after each kind of failure
clio-runtime-configThe config file outside compose, environment variables, the clio-run commands, multi-node and Docker
clio-bdevBlock devices and storage tiers, and the erasure-coded safe_bdev array
clio-cte-coreThe CTE core's keys, and the C++ and Python blob API
clio-cte-cachesThe write-back, write-thru, shared-memory and node-copy caches
clio-replicationCopies on other nodes, failover and hand-back
clio-compressorTransparent compression and its codecs
clio-indexerKeyword search over stored data
clio-fsThe filesystem and stream modules, and mounting with FUSE
clio-caeImporting data with OMNI files and clio-cae, and the summarizer
chimod-devWrite, build and load a new ChiMod or data-path operator outside the CLIO Core repository
gpu-vectorWrite and tune GPU kernels over the paged out-of-core vector

This tutorial uses storage-compose, which loads the module skills as it writes each entry.

2. Install the launcher

The clio-kit command installs skills into an agent's skill directory.

Release

$ uv tool install clio-kit
$ clio-kit skill list --bundle clio-core

If the list is empty, your release predates the clio-core bundle. Use the checkout route.

Checkout

$ git clone https://github.com/iowarp/clio-kit.git
$ cd clio-kit
$ uv tool install --force --reinstall --editable .
$ clio-kit skill list --bundle clio-core

Keep the checkout: an editable install reads the skills from it.

The list names the twelve skills in the table above. If clio-kit is not found, run uv tool update-shell and open a new shell.

3. Install the skills into your agent

Run these from the project directory where you will work with the agent.

Claude Code

Claude Code installs the bundle as a plugin from the CLIO Kit marketplace:

$ claude plugin marketplace add iowarp/clio-kit
$ claude plugin install clio-core-skills@clio-kit

From a checkout, pass its path to marketplace add instead of iowarp/clio-kit. To copy the skill folders into the project instead, use clio-kit skill install --bundle clio-core --target .claude/skills.

Codex

$ clio-kit skill install --bundle clio-core --target .agents/skills

Use ~/.agents/skills to make them available in every project.

Cursor

$ clio-kit skill install --bundle clio-core --target .cursor/skills

Other agents

Give --target the directory your agent reads skills from. VS Code, Cursor and Antigravity also read .agents/skills.

$ clio-kit skill install --bundle clio-core --target <skill directory>

Start a new agent session so it picks up the skills.

4. Describe the system you need

Name the hardware, and the failures your data must survive with how much loss you accept. The skill turns those into module choices; adjectives such as "durable" or "fast" leave the agent guessing.

Write a clio.yaml compose section for one node with 64 GB of DRAM and a
2 TB NVMe drive mounted at /mnt/nvme. Data the application has fsynced
must survive a runtime crash; losing a few seconds of unsynced writes is
fine. State what an acknowledged put means, and what a kill -9 loses.

A good answer has:

  • Two CTE cores: a persistent one at 512.0 on the NVMe file tier and a volatile one at 540.0 on DRAM.
  • The replication module, and the write-back cache over both cores.
  • persistence_level set on the NVMe tier and performance.metadata_log_path set on the persistent core.
  • A statement that a put is acknowledged once it is in DRAM, that fsync is the durability point, and that a crash loses writes not yet flushed (up to flush_period_ms).

Add what your setup really needs: more nodes and a node that may fail, a drive that may fail, a POSIX mount, search, or compression. The agent adds replication, an erasure-coded array, the filesystem and stream modules, the indexer or the compressor to match.

5. Review what it wrote

Check these before you run it. Each one is a mistake that starts cleanly and fails later.

  • Order. Every entry comes after each pool it names in next_pool_id, next_volatile, next_persistent, flush_pool or existing_pool_id.
  • Unique pool ids. A second pool with a taken id is reported as created and is never made.
  • Durable tiers say so. A tier without persistence_level is volatile, even a file on NVMe.
  • Metadata is logged. Without metadata_log_path, the bytes survive a restart but nothing records which blob they belong to.
  • No volatile and persistent devices in one core. Two cores joined by the write-back cache, not one mixed core.
  • Search and labeling are scoped. The indexer's tag_re and the summarizer's rules match only the data you need searched or labeled.

Every key is described in the module skills, in the commented default config (~/.clio/clio.yaml after a pip install), and on the module pages.

6. Start it and test the claim

$ CLIO_SERVER_CONF=$PWD/clio.yaml clio-run start &

Open the dashboard's Pools page (Navigate the dashboard) and check that every pool in the file is listed. Then ask the agent to prove the durability statement it made:

Write and run a crash test for this deployment: write data, fsync it,
kill -9 the runtime, start it again without --fresh, and read the data
back. Repeat without the fsync and report what was lost.

The fsynced data must come back. What the run without fsync loses must match the window the agent stated in step 4. If it does not, the configuration or the statement is wrong: show the agent the result and have it fix one or the other.
