The model

A vector is a CTE tag. Page p of the vector is the blob named p in decimal, page_bytes long, written at blob score 0.5. In front of the tag sits a set-associative page cache: nsets sets of set_size frames, with a page's home set computed from its number. The program drives the cache explicitly with four verbs:

  • Fetch makes the named element ranges resident and pins their pages.
  • HoldPage returns a view onto the part of a range that lies on one page. It never fetches: holding a page that was not fetched is an error.
  • Flush writes the named element ranges back to the CTE. There is no dirty bit, so a page you wrote and never flushed is lost when it is evicted.
  • UnpinRange releases the pins a Fetch took. A page that is never unpinned can never be evicted.

A fetch transfers only the elements it names, and a hold may read only elements that were fetched. To treat whole pages, pair PageLo(off) with PageSpan(off, count). Ranges are given as (offset, count) pairs in elements, up to kMaxFetchRanges (8) pairs per call. The first argument of Fetch and Flush is a generation: 0 for an ordinary transfer, otherwise a generational one, where a flush stamps the generation and a fetch waits until the writer has published at least that generation. A page that has no blob yet reads as zeros.

Because pages are ordinary blobs, a cpu_vector and a gpu_vector opened on the same tag with the same page_bytes and element type see the same data, and any CTE client (C++ or the Python API) can read a page as a blob. Data imported by the Context Assimilation Engine lands in tags as blobs; it is readable through a vector only when its blobs are named by page number and hold page_bytes each, which is the layout the vectors write.

cpu_vector

Header clio_cte/cpu_vector/cpu_vector.h, namespace clio::cte::cpu_vector, CMake target clio::cte::cpu_vector. It is header-only, needs no GPU toolchain and is always built. The verbs block instead of suspending, and every verb is thread-safe, so any number of host threads can share one vector. A caller error throws std::runtime_error.

Constructor

Vector(const std::string &tag_name, u64 page_bytes, u64 num_elems,
       u32 nsets, u32 set_size,
       clio::run::PoolId storage_pool_id = clio::run::PoolId::GetNull(),
       int compress_lib = 0, int compress_preset = 1,
       u32 capacity_pages = 0);
  • tag_name: the CTE tag, created if it does not exist.
  • page_bytes: page granularity. Must be a multiple of sizeof(T).
  • num_elems: logical length. The last page may be partial.
  • nsets, set_size: cache geometry; the cache holds up to nsets * set_size pages.
  • storage_pool_id: the pool puts and gets go to; null means the CTE core pool.
  • compress_lib, compress_preset: CTE compression context for every page; 0 is none.
  • capacity_pages: page-sized regions backing the frames; 0 means one per frame. A smaller value makes the frames tags over a tighter memory budget.

Verbs and views

template <typename... Args> void Fetch(u64 generation, Args... off_count_pairs);
Held<T> HoldPage(u64 off, u64 count, bool write = false);
Held<T> UpdateRange(u64 off, u64 count, bool write = false, u64 generation = 0);
template <typename... Args> void Flush(u64 generation, Args... off_count_pairs);
void UnpinRange(u64 off, u64 count);
void UnpinRange2(u64 off0, u64 count0, u64 off1, u64 count1);

Held<T> indexes by absolute element offset: h[off] for off in [h.begin_off(), h.begin_off() + h.run()). ptr() is the raw pointer, run() the element count on this page, and Rescore(rank) sets the frame's eviction rank (lowest is evicted first). A read hold requires the elements to have been fetched; a write hold marks them valid. UpdateRange is Fetch of the whole pages under the range followed by HoldPage.

Host data movement and cache control

  • Preload(const T *src, u64 n) and PreloadPages(pg_lo, pg_hi, fill) write straight to the CTE, bypassing the cache.
  • Download(T *dst, u64 n) and DownloadPages(pg_lo, pg_hi, sink) read straight from the CTE. Flush first.
  • Prefetch(pg_lo, pg_hi) makes pages resident, best effort, and leaves them unpinned.
  • FlushResidentToCte() writes every resident frame's valid elements back.
  • ClearCache() drops every resident page and discards unflushed writes.
  • Copy(new_name, sync = false) makes a copy-on-write snapshot through the checkpoint ChiMod; MaterializeAll() forces its pages to real bytes server-side; ScoreAllPages(score) rescores every page, for draining a checkpoint out of the fast tier.
  • PrefetchNow(hints) and DrainPrefetch() send tier-placement hints (a page number and a score) as batched rescores.
  • EnableStats(), ReadStats(), ReadTable(), Occupied(), MaxPageCopies() for diagnostics.

Geometry: size(), PageBytes(), ElemsPerPage(), NumPages(), NumSets(), SetSize(), NumFrames(), PageOf(off), PageLo(off), PageSpan(off, count), TagId().

Example

This follows the adapter's own test. The runtime config composes a CTE core pool with one RAM tier; CLIO_INIT starts a runtime in-process when none is running, and CLIO_CTE_CLIENT_INIT attaches the CTE client.

networking:
  port: 9461
runtime:
  num_threads: 4
  queue_depth: 1024
compose:
  - mod_name: clio_cte_core
    pool_name: clio_cte
    pool_query: local
    pool_id: 512.0
    storage:
      - path: "ram::cpu_vector_dram"
        bdev_type: "ram"
        capacity_limit: "256MB"
        score: 1.0
    dpe:
      dpe_type: "max_bw"

#include <clio_cte/core/core_client.h>
#include <clio_cte/cpu_vector/cpu_vector.h>
#include <clio_runtime/clio_runtime.h>

namespace cv = clio::cte::cpu_vector;
using clio::run::u64;

int main() {
  // CLIO_SERVER_CONF=clio.yaml in the environment.
  if (!clio::run::CLIO_INIT(clio::run::RuntimeMode::kClient, true)) return 1;
  if (!clio::cte::core::CLIO_CTE_CLIENT_INIT()) return 1;

  const u64 page_bytes = 4096;
  const u64 epp = page_bytes / sizeof(u64);      // elements per page
  const u64 n = 6 * epp;
  cv::Vector<u64> v("my_vector", page_bytes, n, /*nsets=*/2, /*set_size=*/4);

  // Write: fetch (unwritten pages read as zeros), hold for write, flush, unpin.
  v.Fetch(0, 0, n);
  for (u64 off = 0; off < n; off += epp) {
    auto h = v.HoldPage(off, epp, /*write=*/true);
    for (u64 i = off; i < off + h.run(); ++i) h[i] = i * 3;
  }
  v.Flush(0, 0, n);
  v.UnpinRange(0, n);

  // Read back through the cache.
  v.Fetch(0, 0, n);
  for (u64 off = 0; off < n; off += epp) {
    auto h = v.HoldPage(off, epp);
    for (u64 i = off; i < off + h.run(); ++i) {
      if (h[i] != i * 3) return 2;
    }
  }
  v.UnpinRange(0, n);

  // Or straight from the CTE, bypassing the cache.
  std::vector<u64> out(n);
  v.Download(out.data(), n);

  clio::run::CLIO_RUNTIME_FINALIZE();
  return 0;
}

gpu_vector

Header clio_cte/gpu_vector/gpu_vector.h, namespace clio::cte::gpu_vector, CMake target clio::cte::gpu_vector. The host class Vector<T> owns the allocations and hands out a DeviceVector<T> that a kernel takes by value. The device side does the paging: a block fetches, holds, flushes and unpins from inside the kernel, and the transfers are completed by the runtime's CPU workers.

Host constructor

Vector(const std::string &tag_name, const std::vector<int> &gpu_ids,
       u64 page_bytes, u32 nblocks, u32 set_size, u64 num_elems,
       clio::run::PoolId storage_pool_id = clio::run::PoolId::GetNull(),
       int compress_lib = 0, int compress_preset = 1,
       u32 nsets = 0, u32 capacity_pages = 0);
  • gpu_ids: the GPUs to build device views for. GetDevice(gpu_id) returns the view.
  • nblocks: the number of blocks the kernel will launch. Each block owns its own fetch and flush task set, so a kernel launched with more blocks than this traps in Init.
  • set_size: frames per associative set. nsets defaults to nblocks; there is one cache for the whole grid, and a page is stored once.
  • capacity_pages: page-sized regions of device memory; 0 means nsets * set_size.
  • storage_pool_id: null means the value of CLIO_GV_STORAGE_POOL (as "major.minor", for example 563.0 to go through the CTE cache module) if set, else the CTE core pool.

Host-side methods

The host never pages. It moves data in and out and controls the cache: Preload, PreloadPages, Download, DownloadPages, Prefetch(pg_lo, pg_hi, gpu_id = 0), ClearCache(gpu_id = 0), FlushResidentToCte(), Copy(new_name, sync = false), MaterializeAll(), ScoreAllPages(score), PrefetchNow(hints), DrainPrefetch(), RegisterPrefetcher(p) with YieldObserver() for a driver-driven prefetcher, EnableStats(), ReadStats(gpu_id), ReadTable(gpu_id), Occupied(gpu_id), MaxPageCopies(gpu_id). A copy made with Copy builds no device views; a kernel that must read it opens its own Vector on the copy's tag.

When a kernel traps, FatalReport() returns the reason the device latched (page not resident, range never fetched, set full, fetch failed, and so on).

Device API

Every DeviceVector function is block-collective: all threads of the block call it together, and no suspension may sit inside a thread-predicated branch. The kernel is a device coroutine run by the yield driver, so the fetching verbs are awaited.

void Init(u32 block);                                   // once, with yv.Block()
co_await v.Fetch(u64 generation, off, count, ...);      // BeginFetch + AwaitFetch
co_await v.BeginFetch(u64 generation, off, count, ...); // submit, then compute
co_await v.AwaitFetch();                                //   ... then wait
Held<T> h = co_await v.HoldPage(u64 off, u64 count, bool write = false);
co_await v.Flush(u64 generation, off, count, ...);
co_await v.BeginFlush(u64 generation, off, count, ...);
void UnpinRange(u64 off, u64 count);
void UnpinRange2(u64 off0, u64 count0, u64 off1, u64 count1);

Geometry on the device: size(), PageBytes(), ElemsPerPage(), NumPages(), PageOf, PageLo, PageSpan, NumSets(), SetSize(), Regions(). Held<T> works as on the CPU: absolute indexing, ptr(), run(), Rescore(rank). Under the clio-coroc transpiler (-DCLIO_COROC) the same verbs are spelled CoFetch, CoHoldPage (returning a PageRef<T>), CoFlush and CoBeginFetch/CoAwaitFetch/CoBeginFlush/CoEndFlush, used with CO_AWAIT.

Example kernel

This is the adapter's smoke test, cut down: one block fills a vector page by page, flushing as it goes, then a second kernel reads it back. Both kernels are coroutines launched through the yield driver, which relaunches parked blocks until none is suspended; gv::ResumeWhenComplete holds a block back until its transfer has landed.

#include <clio_runtime/clio_runtime.h>
#include <clio_runtime/gpu/gpu_ipc_manager.h>
#include <clio_runtime/gpu/yield_stack.h>
#include <clio_runtime/gpu/yieldable.h>
#include <clio_cte/core/core_client.h>
#include <clio_cte/gpu_vector/gpu_vector.h>

namespace gv = clio::cte::gpu_vector;
namespace gy = clio::run::gpu;
using clio::run::u32;
using clio::run::u64;

__device__ gy::YCoroMain FillCoro(gv::DeviceVector<u32> v, u64 n) {
  for (u64 i = 0; i < n;) {
    u64 run = 0;
    {
      co_await v.Fetch(0, v.PageLo(i), v.PageSpan(i, 1));
      auto h = co_await v.HoldPage(i, n - i, /*write=*/true);
      run = h.run();
      for (u64 k = threadIdx.x; k < run; k += blockDim.x) {
        h[i + k] = static_cast<u32>((i + k) * 7 + 1);
      }
    }
    co_await v.Flush(0, i, run);               // the vector never writes back on its own
    v.UnpinRange(v.PageLo(i), v.PageSpan(i, 1));  // Fetch pinned; give the pin back
    i += run;
  }
}

__global__ void FillKernel(clio::run::IpcManagerGpuInfo info,
                           gv::DeviceVector<u32> v, u64 n,
                           gy::YieldableView<> yv, gy::YieldStackView ys) {
  CLIO_GPU_INIT(info, nullptr);
  v.Init(yv.Block());                 // the logical block id, not blockIdx.x
  gy::YieldTlsPublish(ys, yv.Y(), yv.Block());
  __syncthreads();
  CLIO_YCORO_RUN(FillCoro(v, n));
}

__device__ gy::YCoroMain CheckCoro(gv::DeviceVector<u32> v, u64 n,
                                   unsigned long long *bad) {
  for (u64 i = 0; i < n;) {
    co_await v.Fetch(0, v.PageLo(i), v.PageSpan(i, 1));
    auto h = co_await v.HoldPage(i, n - i);
    for (u64 k = threadIdx.x; k < h.run(); k += blockDim.x) {
      if (h[i + k] != static_cast<u32>((i + k) * 7 + 1)) atomicAdd(bad, 1ull);
    }
    const u64 run = h.run();
    v.UnpinRange(v.PageLo(i), v.PageSpan(i, 1));
    i += run;
  }
}

__global__ void CheckKernel(clio::run::IpcManagerGpuInfo info,
                            gv::DeviceVector<u32> v, u64 n,
                            unsigned long long *bad,
                            gy::YieldableView<> yv, gy::YieldStackView ys) {
  CLIO_GPU_INIT(info, nullptr);
  v.Init(yv.Block());
  gy::YieldTlsPublish(ys, yv.Y(), yv.Block());
  __syncthreads();
  CLIO_YCORO_RUN(CheckCoro(v, n, bad));
}

Points the test comments make and that apply to any kernel:

  • Slice by yv.Block(), not blockIdx.x. The driver relaunches a compacted grid, so a block resumes on a different CUDA block than it started on.
  • Every lane runs the loop. A hold synchronizes the block internally; returning early from some threads deadlocks the barrier.
  • Flush as you go. Writing more pages than the cache holds without flushing fills the cache with pages nobody can evict.
  • Several blocks writing one page flush only the element ranges they wrote, so a full-page flush does not clobber a neighbour's part.

A SYCL kernel body is a lambda rather than a __global__ function, so the launch code differs; the device verbs are the same. The SYCL tests live in context-transfer-engine/adapter/gpu_vector/test/sycl.

Configuration

  • Runtime config (CLIO_SERVER_CONF): the compose must contain a clio_cte_core pool with at least one storage tier. Without a tier the first writeback has nowhere to land and never completes. For GPU kernels, set gpu: queue_depth above the number of faulting blocks; the default is 16.
  • Tiers a page reaches. Pages are written at score 0.5. With the max_bw placement engine, a tier whose score is above 0.5 is excluded from the preferred group, so with tiers scored HBM 1.0, host RAM 0.2 and storage 0.0 a page never lands in HBM on its own. A prefetch hint at 1.0 (PrefetchNow, a registered Prefetcher, or ScoreAllPages) is what moves a page into such a tier. See Placement and tiering.
  • CLIO_GV_STORAGE_POOL: the pool a gpu_vector uses when the constructor is given none, as "major.minor".
  • CLIO_WITH_RUNTIME: 0 attaches to a running runtime; 1 makes sure one is available (see Context Runtime).
  • Compression: pass compress_lib and compress_preset to the constructor. Every page is put and got with that context.

Build options

  • cpu_vector builds in every configuration.
  • gpu_vector device code needs a GPU toolchain. For NVIDIA, configure CLIO Core with -DCLIO_CORE_ENABLE_CUDA=ON -DCLIO_GPU_CLANG=ON: the device verbs are C++20 coroutines, which nvcc cannot compile, so clang is the CUDA compiler. For Intel GPUs, -DCLIO_CORE_ENABLE_SYCL=ON with icpx.
  • The adapter's tests are built with CLIO_CORE_ENABLE_TESTS=ON; the CUDA tests are registered under the gpu_vector ctest label, and the SYCL tests under test/sycl.
  • Link your program against clio::cte::gpu_vector (header-only; it pulls in the CTE core and checkpoint clients). The tests also link clio_run_cxx_gpu and ctp::cuda_cxx for the GPU IPC manager and the yield driver.
