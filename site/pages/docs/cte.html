Data model

  • Tag. A named group of blobs, roughly a bucket. Each tag has a TagId with a major_ and minor_ part; the name maps to the id and one container owns the tag. A tag also carries extended attributes (TagXattr) and can have aliases. Context FS uses one tag per file.
  • Blob. A named byte range inside a tag. Puts and gets address a blob by (tag id, blob name) plus an offset and size, so a blob can be written and read in pieces. Blob verbs are routed to the blob's owner container by hashing its tag and name.
  • Score. Every blob has a placement score from 0.0 to 1.0. 1.0 means the fastest tier, 0.0 the slowest. A new blob without an explicit score lands at 1.0; a put that passes the score sentinel -1.0 keeps the blob's current score.
  • Targets and tiers. Each storage entry on the core's compose entry becomes a block-device pool registered as a target with its own score and capacity. Types are ram, file, hbm, pinned, noop, s3 and gcs, or an already composed pool such as safe-bdev through existing_pool_id. Memory tiers are node-local; persistent tiers can be registered from a neighborhood of nodes.
  • Placement. At put time the data placement engine (dpe.dpe_type: max_bw by default, or round_robin, random) picks targets for the blob from its score and the targets' free space. A blob's placement later changes only through reorganization.

The concepts page introduces these terms; the CTE core module page has every configuration key and the design page the internals.

Features

Tiering and placement

Tiers are declared in YAML with a path, a type, a capacity and a score. New data goes to the highest-scoring tier with room. A tier's persistence_level (volatile, temporary, long_term) decides whether it can hold the durable copy that a flush or fsync asks for. The placement page and the compose tutorial cover choosing scores.

Reorganization

ReorganizeBlob gives a blob a new score and moves it to the tier that score selects. Evict frees the lowest-scored blobs off a tier. A periodic data organizer (organizer key: none by default, or frecency, grayscott, cyclic, scatter, hotset) can rescore blobs from their access history; with none, placement changes only through explicit calls.

Queries

  • TagQuery and BlobQuery match tag and blob names against regular expressions and are answered from metadata.
  • SemanticSearch is BM25 keyword search over blob contents, filtered by the same two patterns and cut to the top k. It is served by the indexer module (pool 564.0), not by the core, so the client must be bound to the indexer or to a pool that forwards to it.
  • TemporalSearch returns blobs whose last-modified timestamp lies in an inclusive range, sorted ascending. The Python API page notes that the timestamp is currently a steady clock, not Unix time.

All patterns use full-string matching (std::regex_match): "doc.*" matches doc7, "doc" does not. Queries default to PoolQuery::Broadcast(), so every node answers for its own blobs and the runtime merges the results; PoolQuery::Local() asks only this node.

Asynchronous operations

Every client method has an Async form that returns a future immediately. Call Wait() and read the task's result fields. Deferred puts (AsyncPutBlobDefer) stage a copy and return a submission code at once; the put is tracked in a process-wide registry with a bound on in-flight bytes. Conditional puts, selected with the Context flags kPutIfAbsent and kPutIfVersion, fail with distinct return codes instead of overwriting.

The interposition chain

The core is the bottom of a chain of modules that share its task interface: cache (563.0), indexer (564.0), optional compressor (562.0), replication (561.0), core (512.0). A client bound to the chain top gets all of their behavior; a client bound to 512.0 bypasses them. The chain design page explains the mechanism.

C++ API

Include clio_cte/core/core_client.h and link clio_cte_core_client. Initialize the runtime client with clio::run::CLIO_INIT(clio::run::RuntimeMode::kClient) and the CTE client with clio::cte::core::CLIO_CTE_CLIENT_INIT(); the macro CLIO_CTE_CLIENT then returns the shared client, bound to the pool named by CLIO_CTE_POOL or 512.0 by default. To address another pool directly, construct clio::cte::core::Client with a PoolId.

Tag

The Tag wrapper covers the common case. Its blocking put from a private buffer defaults the score to 1.0; the asynchronous and shared-memory forms default to -1.0, which keeps the existing score.

class Tag {
 public:
  explicit Tag(const std::string &tag_name);   // GetOrCreateTag
  explicit Tag(const TagId &tag_id);           // wrap an existing id, no RPC

  void PutBlob(const std::string &blob_name, const char *data, size_t data_size,
               size_t off = 0, float score = 1.0f, const Context &context = Context());
  void PutBlob(const std::string &blob_name, const ctp::ipc::ShmPtr<> &data, size_t data_size,
               size_t off = 0, float score = -1.0f, const Context &context = Context());
  clio::run::Future<PutBlobTask> AsyncPutBlob(const std::string &blob_name, const char *data,
               size_t data_size, size_t off = 0, float score = -1.0f, const Context &context = Context());
  clio::run::Future<PutBlobTask> AsyncPutBlob(const std::string &blob_name, const ctp::ipc::ShmPtr<> &data,
               size_t data_size, size_t off = 0, float score = -1.0f, const Context &context = Context());

  void GetBlob(const std::string &blob_name, char *data, size_t data_size, size_t off = 0);
  void GetBlob(const std::string &blob_name, ctp::ipc::ShmPtr<> data, size_t data_size, size_t off = 0);
  clio::run::Future<GetBlobTask> AsyncGetBlob(const std::string &blob_name, char *data,
               size_t data_size, size_t off = 0);

  float GetBlobScore(const std::string &blob_name);
  clio::run::u64 GetBlobSize(const std::string &blob_name);
  std::vector<std::string> GetContainedBlobs();
  void ReorganizeBlob(const std::string &blob_name, float new_score);
  const TagId &GetTagId() const;
};

The private-buffer forms need no shared-memory management. A private-buffer AsyncGetBlob that is served from the shared-memory cache returns an empty future: Wait() returns at once and the future must not be dereferenced. The blocking PutBlob(const char*) throws on a non-zero return code.

Example

#include <clio_runtime/clio_runtime.h>
#include <clio_cte/core/core_client.h>

int main() {
  clio::run::CLIO_INIT(clio::run::RuntimeMode::kClient);
  clio::cte::core::CLIO_CTE_CLIENT_INIT();

  clio::cte::core::Tag tag("experiment/run1");
  std::string payload = "Arctic sea ice extent fell to a record low.";
  tag.PutBlob("note0", payload.data(), payload.size());          // score 1.0, fastest tier

  std::string out(tag.GetBlobSize("note0"), '\0');
  tag.GetBlob("note0", out.data(), out.size());

  tag.ReorganizeBlob("note0", 0.2f);                              // demote to a slower tier

  auto *client = CLIO_CTE_CLIENT;
  auto hits = client->AsyncSemanticSearch("experiment/.*", ".*", "sea ice", 5);
  hits.Wait();
  for (const auto &r : hits->results_) {
    // r.tag_id_, r.blob_name_, r.score_
  }

  auto del = client->AsyncDelBlob(tag.GetTagId(), "note0");
  del.Wait();
  return del->return_code_;
}

For the semantic search to return anything the process must be bound to the indexer: set CLIO_CTE_POOL=564.0 before CLIO_CTE_CLIENT_INIT, or construct a Client on that pool.

Python API

The module clio_cte_core_ext is built with nanobind from context-transfer-engine/wrapper/python/core_bindings.cc and ships in the iowarp-core wheel. Payloads are bytes. Every blocking call releases the GIL. The Python API reference lists each call with its return type; this section summarizes the shape and adds what that page leaves out.

Setup

import os
os.environ["CLIO_WITH_RUNTIME"] = "0"     # attach to a running clio_run
os.environ["CLIO_CTE_POOL"] = "564.0"     # indexer, so SemanticSearch works

import clio_cte_core_ext as cte
cte.clio_init(cte.RuntimeMode.kClient, False)   # (mode, default_with_runtime=False, is_restart=False)
cte.initialize_cte("", cte.PoolQuery.Dynamic())  # (config_path, pool_query)
client = cte.get_cte_client()

Tag

Tag(tag_name) creates or opens a tag; Tag(tag_id) wraps an id without an RPC. Methods: PutBlob(blob_name, data, off=0), GetBlob(blob_name, data_size, off=0) returning bytes, GetBlobScore(blob_name), GetBlobSize(blob_name), GetContainedBlobs(), ReorganizeBlob(blob_name, new_score) and GetTagId(). GetBlob raises RuntimeError when the read fails. There is no score argument on the Python PutBlob; use ReorganizeBlob to move a blob.

Client

Blocking calls: TagQuery(tag_regex, max_tags=0, pool_query=Broadcast()) returns tag names; BlobQuery(tag_regex, blob_regex, max_blobs=0, pool_query=Broadcast()) returns (tag_name, blob_name) pairs; SemanticSearch(tag_regex, blob_regex, query_text, k=10, pool_query=Broadcast()) returns SemanticSearchResult objects (tag_id, blob_name, score) best first, with k=0 meaning no cap; TemporalSearch(tag_regex, blob_regex, time_begin=0, time_end=0, max_entries=0, pool_query=Broadcast()) returns TemporalSearchResult objects (tag_id, blob_name, last_modified); ReorganizeBlob(tag_id, blob_name, new_score) and DelBlob(tag_id, blob_name) return True on success; PollTelemetryLog(minimum_logical_time) returns CteTelemetry entries; RegisterTarget(target_name, bdev_type, total_size[, target_query, bdev_id]) returns 0 on success.

Asynchronous calls return a Future with wait(max_sec=-1) (returns the return code, or None on timeout), done() and result(max_sec=-1), whose value depends on the call: bytes for AsyncGetBlob, a dict for conditional puts and versioned gets, a list for queries. They are AsyncGetOrCreateTag(tag_name, pool_query=Dynamic()) (result is the tag id), AsyncPutBlob(tag_id, blob_name, data, off=0), AsyncPutBlobIfAbsent(tag_id, blob_name, data, off=0), AsyncPutBlobIfVersion(tag_id, blob_name, data, version, off=0), AsyncGetBlob(tag_id, blob_name, data_size, off=0), AsyncGetBlobVersioned(tag_id, blob_name, data_size, off=0), AsyncGetBlobSize(tag_id, blob_name, pool_query=Dynamic()), AsyncGetContainedBlobs(tag_id, pool_query=Broadcast()), AsyncDelBlob(tag_id, blob_name), AsyncReorganizeBlob(tag_id, blob_name, new_score), AsyncTagQuery, AsyncBlobQuery, AsyncSemanticSearch, AsyncTemporalSearch, AsyncPollTelemetryLog, AsyncRegisterTarget, AsyncGetCapacity, AsyncListTargets, AsyncStatTargets and AsyncGetTargetInfo.

Deferred puts differ: AsyncPutBlobDefer(tag_id, blob_name, data, off=0, max_inflight_bytes=0) stages a copy and returns an int submission code (0 = submitted), not a future. AwaitPutsUntilSpace(max_inflight_bytes) waits until at most that many payload bytes are in flight (0 drains all), DeferErrorCount() counts deferred puts that failed, and AsyncGetBlobDefer(tag_id, blob_name, data_size, off=0) completes pending deferred puts for the blob before reading.

Supporting types: UniqueId(major, minor) (the tag id type, with major_, minor_, IsNull(), ToU64()), PoolQuery.Broadcast(), PoolQuery.Dynamic(), PoolQuery.Local(parallelism=32), the enums RuntimeMode, BdevType (kFile, kRam) and CteOp, and CapacityInfo, TargetInfo and CteTelemetry.

Example

tag = cte.Tag("experiment/run1")
tag.PutBlob("note0", b"Arctic sea ice extent fell to a record low.", 0)
tag.PutBlob("note1", b"Atmospheric CO2 passed 420 ppm.", 0)

size = tag.GetBlobSize("note0")
data = tag.GetBlob("note0", size, 0)            # bytes

for tag_name, blob_name in client.BlobQuery("experiment/.*", "note.*"):
    print(tag_name, blob_name)

for hit in client.SemanticSearch("experiment/.*", ".*", "sea ice", k=5):
    print(hit.blob_name, hit.score)             # best first; 0 means no query word

tag.ReorganizeBlob("note1", 0.0)                # slowest tier

futs = [client.AsyncGetBlob(tag.GetTagId(), n, tag.GetBlobSize(n), 0) for n in ("note0", "note1")]
payloads = [f.result() for f in futs]

client.DelBlob(tag.GetTagId(), "note0")
