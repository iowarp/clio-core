The short version

You start one background process per node, the runtime, with a YAML file that lists the modules and storage tiers you want. What you put in front of them decides the product you get: Context FS mounts a directory that any program can use, the key-value store gives C++ and Python direct access to tags and blobs, memory expansion pages GPU and CPU arrays larger than memory, and clio-ml trains models on that data. The quickest way to see it work is the filesystem, so these docs start there.

Underneath every product, CLIO Core decides where each piece of data lives. Recently used data stays in RAM. Colder data moves to NVMe or disk. A persistent copy protects it across restarts. An index records the words in each file, so you can later ask "which files mention sea ice extent?" and get a ranked answer.

What you can do with it

01

Mount a filesystem

Start the runtime, mount a directory, copy data in, and unmount. Takes about five minutes.

 02

Compose storage tiers

Combine RAM, NVMe, SSD and disk in one store with a short YAML file.

 03

Search from Python

Find files by keyword relevance or name pattern, and read them back.

 04

Watch the runtime

See nodes, workers and storage tiers live in the built-in web dashboard.
