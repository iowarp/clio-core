Host side and device side

The work is split in two. The host side creates the vector, makes every allocation, and gives the kernel a device view. A kernel cannot allocate anything, so all memory a kernel will ever touch is sized before launch. The device view is the only thing the kernel sees.

Pages

The vector is cut into fixed-size pages. Page N is stored as a CTE blob named p<N>, so pages get every CTE property for free: placement across tiers, persistence, and the chain of modules. Pages are divided among GPU blocks: block b owns a contiguous range of pages, so two blocks never fight over the same page.

The per-block page cache

Each block keeps a small cache of pages in device memory. Every public call is block-collective: all threads of the block make it together. Because a block owns its pages and its cache, nothing needs a lock.

Slots and regions
A slot is a 64-byte tag that points to a memory region only while it holds a page. Regions are owned per block. Making the cache more associative therefore costs extra tags, not extra pages of memory.
Eviction
Each freshly faulted page starts at an eviction rank; a higher rank means keep it longer.
Fetch
A kernel brings a page in with a begin/await pair, so it can start a fetch and keep computing while the page arrives.
Flush
Dirty pages are written back to the CTE through a hold-and-flush path.

Prefetch hints

The prefetcher does not copy pages into the GPU cache; only the kernel does that. Instead it uses the state of yielding blocks to predict which pages are next and sends tier hints through the CTE's bulk rescore call, so those blobs move to a faster tier before the kernel asks for them.

Where missing data comes from

A page that is not in the CTE yet is faulted in by the same mechanism the CAE uses: the CTE misses, asks the CAE, and the CAE produces the page from the original source. That is how a file larger than memory can be opened as a vector without staging it first.

Backends

The adapter has CUDA, SYCL and CPU backends; adapter/cpu_vector provides the same model on host threads. Communication timing can be compiled in with the opt-in GV_COMM_TIMING build flag.
