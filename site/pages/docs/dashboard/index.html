Open it

Start the runtime and open the address it logs:

$ clio-run start &

Viz: dashboard listening at http://127.0.0.1:8080

The bar at the top has three tabs, Cluster, Pools and Config, and a connection indicator on the right. Pages for a module, such as CTE, add their own tab when you open them. To use another port, reach it on a remote node, or run it in Docker, see usage.

No authentication

Anyone who can reach the dashboard can create and destroy pools. It listens on loopback by default. Do not bind it to a public interface without a reverse proxy that controls access.

The screenshots below come from one Windows node running the default configuration while a short benchmark writes to it.

Cluster

The landing page. One card per node shows its address and whether it is alive, with leader and this node badges. Under This node are CPU and memory meters and a worker summary: how many tasks are queued, blocked and processed.

A node

Click a node card to see its utilization and one row per worker thread: whether it is active, its queued, blocked, periodic and retried tasks, how many it has processed, its load and how long it sleeps between polls.

Pools

Everything composed on this node, grouped by module: the runtime itself (clio_admin), block devices (clio_bdev), the storage engine (clio_cte_core), the module chain, the filesystem and the importers. Add Pool creates a new one from a form, and the × on a card destroys that pool after you confirm. Click a card to open its page.

Context Transfer Engine

The page of a clio_cte_core pool lists its storage tiers, the targets data placement chooses between, with each one's score, free space, capacity, latency, bandwidth and bytes moved. Register bdev adds a tier while the runtime runs; the button at the end of a row removes one.

A block device

A clio_bdev pool's page has a capacity meter and every statistic the device reports. Below it, like every module page, is the scheduler's learned cost model for the pool's methods.

Config

What the daemon actually came up with after the config file, environment variables and command-line flags were applied: ports, hostfile, worker counts, scheduler, dashboard address and loaded modules. Below that is every REST route and the module that registered it. Check here first when a setting seems to have no effect.
