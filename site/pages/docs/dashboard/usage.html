Choose where it listens

By default the dashboard listens on 127.0.0.1:8080. Each setting can come from a flag, an environment variable or the viz section of the runtime configuration:

SettingFlagEnvironmentYAML (viz:)Default
Serve the dashboard--viz / --no-vizCLIO_VIZ_ENABLEenabledon
Port--viz-port <port>CLIO_VIZ_PORTport8080; 0 picks a free port
Bind address--viz-bind <addr>CLIO_VIZ_BINDbind127.0.0.1
HTTP threadsCLIO_VIZ_MAX_THREADSmax_threads16

Another port

$ clio-run start --viz-port 9000 &

Remote host

# On your laptop, then open http://127.0.0.1:8080 locally
$ ssh -L 8080:127.0.0.1:8080 user@node1

Docker

services:
  iowarp:
    image: iowarp/deploy-cpu:latest
    environment:
      - CLIO_VIZ_BIND=0.0.0.0
    ports:
      - "9413:9413"
      - "8080:8080"
    command: ["clio-run", "start"]

In clio.yaml

viz:
  enabled: true
  port: 8080
  bind: "127.0.0.1"
  max_threads: 16

Inside a container, binding 0.0.0.0 is what lets the published port reach the dashboard; keep the published port on a trusted network. The pip wheel includes the dashboard. A source build includes it only when CMake finds the Poco HTTP library at configure time; without it the runtime logs this build has no HTTP transport and serves no dashboard.

Create a pool from the browser

  1. On Pools, click Add Pool and choose clio_bdev.

  2. Fill in the form: pool_name ram::scratch, keep the suggested pool_id, bdev_type ram, capacity 256MB.

  3. Click Validate. Each field is checked, nothing is created, and errors come back per field.

  4. Click Create. A new card appears under clio_bdev. Click it to watch the device.

Block devices, safe block devices and the CTE core have typed forms. Other modules get a compose editor: identity fields plus a YAML box that takes anything you could put in the compose section of clio.yaml. S3 and GCS block devices are left out of the form because they need credentials; compose those from a file (see cloud storage).

Add or remove a storage tier

Open the clio_cte_core pool from Pools. Under Register bdev, give the target a name, pick a type and capacity, and click Register; to reuse an existing block device pool, put its id in attach pool instead. The new row appears in the targets table and data placement starts using it at once. The button at the end of a row unregisters that tier.

Watch a workload

Keep the dashboard open while something writes to the runtime, for example a copy into a Context FS mount:

$ cp -r ~/datasets/era5-sample ~/clio-mnt/

  1. Cluster → This node: the processed count climbs and the worker meters move.

  2. Pools → clio_cte_core: the RAM tier's free space drops, then slower tiers' bytes written grows as data moves down.

  3. Pools → clio_bdev: the block device's capacity meter fills.

Destroy a pool

The × in a pool card's corner destroys that pool and its containers on this node, after you confirm. The admin pool has no ×: it is the runtime itself.
