The pieces

The context interface

All logic lives in one C++ class in the caller's process. Constructing it does nothing; the first operation initializes the runtime client, then the CAE client (which brings up the CTE client), and checks that the runtime client is up. A failed runtime initialization is remembered rather than retried in a loop, because repeatedly creating the messaging context corrupted the allocator under Python 3.13.

Operations

Bundle
Builds assimilation contexts from the caller's list and sends them to the CAE core as one ParseOmni task, then waits. Everything the CAE can import, the CEE can bundle.
Query
Returns matching blob names in one of three modes. With a time bound it runs a temporal query. With a text query it runs the CTE's BM25 semantic search, served by the indexer, with a positive top-k (10 if none is given). Otherwise it runs a regular-expression query over tag and blob names.
Retrieve
Resolves names with the same three modes, then fetches the blobs in batches: it looks up each size, allocates one shared buffer, issues the gets of a batch asynchronously and waits for them together, and returns the packed bytes. A blob that would overflow the buffer ends its batch; later batches still add blobs that fit. Missing and empty blobs are skipped.
Destroy
Deletes each named context's tag through the CTE.

A splice operation is declared but not yet implemented.

The MCP server

iowarp-cei-mcp is a Python server (FastMCP) that gives AI agents tools over the Model Context Protocol. It wraps the CTE's Python bindings (clio_cte_core_ext), not the context interface: its tools query tags and blobs by regular expression, put, get, size and delete blobs, rescore a blob, and poll the telemetry log.
