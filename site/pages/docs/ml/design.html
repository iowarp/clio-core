Datasets are pages

A dataset is a page-aligned, row-major table of 32-bit floats stored in a memory-expansion vector. A page is the unit of work, and no row may straddle a page boundary, so the page must hold a whole number of rows; the dataset refuses a page size that does not. The vector is one CTE tag with one blob per page, named by the page's index. Data gets there through a host preload that writes every page, which is what the Python front end does, or through the CAE, which can serve page numbers over data it has ingested.

How a dataset is laid out

One code path for GPU and CPU

The backend selects the GPU vector by default, or the CPU vector on host threads when the code is built with CLIO_ML_CPU=1. Both run the same per-row math in the same order, so a CPU fit and a GPU fit of one dataset agree to the bit wherever the host and device math libraries agree (operations that need it use exact exp/log routines).

One pass through the page cache

Deterministic reductions

Each GPU block computes its own partial result (sums, counts, gradients). Partials are combined in a fixed order instead of with global atomic adds. That is slightly more work, but it makes every run reproducible. A paged kernel that hits the yield driver's round cap throws instead of returning the result of a partly executed pass.

Each algorithm is a runtime module

Every algorithm (k-means, random forests, gradient boosting, PCA, LSTMs and more) is packaged as its own runtime module named clio_ml_<algo>_chimod. The modules share one container template; each algorithm adds only a short adapter that calls its fit function. Besides the standard create, destroy and monitor methods, each has a compute method that the client sends to every container at once with a broadcast query. Because it is an ordinary module, an algorithm is installed, composed and monitored like any other.

Training across a cluster

Each container opens its own shard of the dataset, named <tag>_n<container id>. Per-block partials are gathered from all nodes in node order, so a fit across N nodes is bit-identical to a single-node fit with N times as many blocks. When results come back, one model is kept and any replica that disagrees is flagged, which catches nondeterminism bugs.
